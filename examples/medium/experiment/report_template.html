雾化方法对照实验

同一个动画场景、同一团地面雾，分别用无雾 baseline、Cycles 体积路径追踪、ray marching 和闭式解（可加多次散射，以及物体投下的光柱和对天空的遮挡）生成带雾画面，再喂给 RGB、被动 SPAD、DVS 和 ToF 四种仿真传感器，对比闭式解省下的时间和损失的精度。真值有两个：物理上完整的多次散射，以及 Blender 默认、和闭式解模型一致的单次散射。

实验设置

场景
演示场景（examples/medium/demo_scene.py）：棋盘格地面、4 个方块、7 根柱子。太阳高度角 30°、辐照度 4 W/m²，天空辐射度 (0.25, 0.35, 0.55)。相机离地 1.6 m，前进 24 m 并同时转动，关键帧拉伸 5 倍，得到 125 fps × 500 帧。
雾
地面雾 media/ground_fog.json：σ(z) = 0.08·e−z/2.5 m⁻¹，反照率 1，HG 相函数 g = 0.8，阳光和天光在雾中都会衰减。Cycles 里是一个 400×400×26 m 的体积盒，密度函数完全相同。
参考真值
两套参考，都是 Cycles 体积路径追踪，4096 spp，关闭自适应采样和降噪：多次散射（最多 16 次体积弹射，8 次时已收敛）和单次散射（Blender 默认的 0 次体积弹射）。每套都换一个随机种子再渲染一遍，两者之差就是参考自身的噪声底。
闭式解与 ray marching 的输入
无雾场景用 visionsim 默认设置渲染（256 spp，自适应采样，降噪），输出线性 EXR、深度和 lighting.json。雾是事后加上去的，渲染帧只算一次。
方法雾怎么来
无雾 baseline原始 visionsim 流程，不加雾。它的 loss 就是"完全忽略雾"会造成的误差。
Cycles 默认设置把雾的体积放进场景，用 visionsim 默认的渲染设置（256 spp，自适应采样，OIDN 降噪）直接渲染，也就是"真实体积渲染"的常规做法。分别渲染了多次散射（最多 16 次体积弹射）和单次散射（Blender 默认的 0 次）两个版本。
Cycles 不降噪同上，但关闭降噪，画面保留蒙特卡洛噪声，用来检验渲染噪声对光子级传感器的影响。
Ray marching新增的 visionsim.medium.ray_march_medium：沿每条视线均匀分步做数值积分，每步内按能量守恒的方式积分。16 步版本中，光照衰减用解析式；64+16 步版本中，每个采样点再朝太阳方向走 16 步，这是通用体积渲染器的做法。它和闭式解积分的是同一个单次散射模型，只是换成了数值积分。
闭式解（修正天光前）上一版 M1 的光照模型：天空被当作来自整个球面的均匀光，并且不被雾衰减。
闭式解当前模型（单次散射）：天光只来自上半球（下半球被地面遮挡），按相函数加权，并且被雾衰减。每个方向的衰减都有闭式解，方向积分用固定求积，结果确定、没有噪声。
闭式解 + 阴影同上，再用场景的阴影图让物体在雾里投下阴影（光柱）、遮挡雾中各点能看到的天空。阴影图每个场景渲染一次（export_occlusion.py），沿视线采样可见性，采样点之间仍用闭式解积分。可见性每帧追踪一次，多组雾参数共用。
闭式解（多次散射）加上地面反射和多次散射的近似（只在以多次散射为真值的对照里出现），可以再加阴影。
传感器设置loss（都在期望测量值上计算，排除传感器自身噪声）
RGB25 fps，每次曝光合并 5 帧（40 ms），每帧每单位辐射度 100 个光子，满阱 500，读出噪声 5，12 bit无噪声 8 位输出的 PSNR、SSIM；线性曝光图的相对 L1
被动 SPAD125 Hz 二值帧，检测概率 p = 1 − e−λ检测概率的 MAE、相对 L1，以及伯努利分布之间的 KL 散度（每像素每帧损失多少比特信息）
DVSv2e，正负阈值 0.2，关闭阈值抖动、散粒噪声和漏电事件（输出只取决于输入画面）按 40 ms 窗口、像素和极性统计事件数，与参考的 F1（1 表示完全一致）
ToF / 主动 SPC905 nm 闪光，1000 个 0.4 ns 的 bin（量程 60 m），脉宽 1 ns，每帧 500 个激光周期，首光子 SPAD 加 Coates 校正；背景光取自各方法自己算出的被动辐射度期望直方图的相对 L1（包括只算激光回波和含背景光两种）；测距与参考不一致的像素比例（差 > 15 cm）

复现

代码都在 examples/medium/experiment/ 下，渲染输出在 runs/fog-comparison/（已被 git 忽略）。在仓库根目录的 PowerShell 里先激活 visionsim 的环境（例如 conda activate .\.conda），并确保 blender 在 PATH 里，然后依次运行：

blender -b --factory-startup --python examples/medium/demo_scene.py -- runs/fog-comparison/demo.blend
blender -b runs/fog-comparison/demo.blend --python examples/medium/experiment/add_fog.py -- examples/medium/media/ground_fog.json runs/fog-comparison/fog_default.blend
blender -b runs/fog-comparison/demo.blend --python examples/medium/experiment/add_fog.py -- examples/medium/media/ground_fog.json runs/fog-comparison/fog_ref.blend --no-adaptive
pwsh examples/medium/experiment/render_all.ps1        # 无雾 + Cycles 默认设置（单次散射）
pwsh examples/medium/experiment/render_refs.ps1       # 单次散射参考（两个种子）
pwsh examples/medium/experiment/render_nodenoise.ps1  # Cycles 不降噪（单次散射）
pwsh examples/medium/experiment/render_ms.ps1         # 多次散射：Cycles 默认、不降噪、参考（两个种子）
blender -b runs/fog-comparison/demo.blend --python examples/medium/experiment/export_lighting.py -- runs/fog-comparison/clear/lighting.json
blender -b runs/fog-comparison/demo.blend --python examples/medium/experiment/export_occlusion.py -- runs/fog-comparison/occlusion/occlusion.npz --exclude Plane > runs/fog-comparison/occlusion/export.log
$env:PYTHONPATH = "examples/medium/experiment"; python examples/medium/experiment/run_experiment.py
python examples/medium/experiment/run_experiment.py --truth multiple   # 结果在 results_ms
python examples/medium/experiment/error_regions.py    # 多次散射真值下误差按区域和方向拆分
blender -b runs/fog-comparison/demo.blend --python examples/medium/experiment/render_passes.py -- runs/fog-comparison/lightgroups --samples 1024 --frame 255 345 --no-volume-passes --light-groups
python examples/medium/experiment/error_sources.py     # 第 255、345 帧的误差来自哪部分光，需要先渲染下文的 32 次弹射
python examples/medium/experiment/temporal.py         # DVS 一节的对数亮度误差
pwsh examples/medium/experiment/timing_1080p.ps1      # 1080p：渲染 10 帧
pwsh examples/medium/experiment/timing_resolution.ps1 -Width 800 -Height 800   # 800×800：渲染 10 帧和参考
python examples/medium/experiment/resolution_check.py # 800×800 下各方法的误差
python examples/medium/experiment/time_methods.py     # 闭式解和 ray marching 的计时，需要 GPU 空闲
python examples/medium/experiment/shadow_reuse.py     # 多组雾参数共用阴影的误差和计时，计时同样需要 GPU 空闲
New-Item -ItemType Directory -Force runs/fog-comparison/cycles_timing
foreach ($blend in "demo", "fog_default", "fog_default_ms") {{ foreach ($size in "800x800", "1920x1080") {{   # Cycles 的计时，同样需要 GPU 空闲
  $width, $height = $size -split "x"
  blender -b runs/fog-comparison/$blend.blend --python examples/medium/experiment/time_cycles.py -- --width $width --height $height > runs/fog-comparison/cycles_timing/${{blend}}_$size.log }} }}
python examples/medium/experiment/validate_lighting.py   # 无物体场景和点光源的验证，渲染步骤见脚本说明
python examples/medium/experiment/validate_occlusion.py  # 第 255 帧上光柱和天空遮挡与 Cycles 的对照
python examples/medium/experiment/make_report.py

误差拆解用 breakdown_scenes.py 生成几种光源变体场景，再用 render_passes.py --frame 255 渲染，最后由 breakdown.py 汇总。多次散射的影响：用 render_passes.py --samples 1024 --frame 255 345 --volume-bounces N 把两帧以 N = 0、1、2、4、8、16、32 次体积弹射各渲染一遍（输出到 runs/fog-comparison/bounces/N），再由 bounces.py 汇总。
